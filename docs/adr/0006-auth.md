# 0006 — Autenticação por JWT/OIDC validado na API

**Contexto.** Mesma conta em quatro plataformas; login em app de carro deve ser raro (sessão longa)
e seguro.

**Decisão.** A API valida tokens JWT com o JWKS de um provedor de identidade (OIDC) e mapeia o
`sub` para `users.auth_subject`. A autorização (papéis, plataforma) é sempre do GoClient, nunca
do provedor.

**Provedor (a escolher na fase de autenticação).** Critérios: SDK para React Native e Next,
login social, recuperação de senha, MFA, preço por usuário ativo, dados no Brasil/LGPD.
Candidatos: Supabase Auth (combina com Postgres gerenciado), Clerk, Auth0, ou solução
auto-hospedada (Better Auth). A API não muda entre eles: só `AUTH_JWKS_URL`, `AUTH_ISSUER`,
`AUTH_AUDIENCE`.

**Automotive.** Digitar senha na central é ruim. Proposta: **login por código** — a central
mostra um código/QR e o usuário confirma no Mobile (fluxo "device authorization", RFC 8628).

**Consequências.** Modo `dev` sem provedor para desenvolvimento local; a API recusa esse modo em
produção.
